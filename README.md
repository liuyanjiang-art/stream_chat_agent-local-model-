# Local Ollama Chat WebUI 本地大模型对话平台
基于 LangChain + Ollama + Gradio 实现的本地大模型对话Web应用，支持多会话隔离、流式输出、会话持久化（内存），所有配置通过环境文件管理，**无需修改源代码**。
项目适合本地私有化部署，对接 Ollama 运行的开源大模型（Qwen、Llama3、Phi3等）。

## ✨ 项目亮点 & 功能
- ✅ **并发与并行能力**：基于Gradio Queue实现多请求排队调度，支持多路对话请求并发；Ollama可开启多并行推理，在显存充足时GPU同时处理多条推理任务；异步流式循环中增加 asyncio.sleep 做流控，平滑token推送节奏，避免前端DOM高频渲染卡顿、任务饥饿。
- ✅ **流式逐字输出**：使用 `ChatOllama.astream` 实现模型打字机流式回复
- ✅ **多会话管理**：新建会话、清空会话、手动输入会话ID加载历史对话
- ✅ **消息格式分层隔离**：LangChain消息对象（`HumanMessage/AIMessage/SystemMessage`） 和 Gradio前端渲染字典分离，规避LangChain与Gradio Chatbot的数据格式冲突问题
- ✅ **环境配置解耦**：所有服务地址、模型名称、端口全部放在 `.env` 文件，修改配置无需改动源码
- ✅ **请求队列控制**：Gradio Queue 限流，支持设置并发数，适配 Ollama 并行推理限制
- ✅ **会话历史加载**：支持加载过往对话上下文，大模型可以记住同一会话内历史信息
- ✅ 轻量无数据库：会话存储在内存字典，快速上手，零额外依赖

  ## 🛠️ 技术栈
| 依赖 | 用途 |

 ##项目不足之处
 1.无法处理高并发，只有单一进程，gradio不适合处理高并发
 2.缺少mcp，skill，hook，插件等功能，功能单一
 3.大模型输出时，chatbot反复渲染，无法拖动滑轮，交互体验差
 4.仅限本机和局域网下的设备可用
 5.上下文容易溢出，未采用向量数据库
 
 

### 新增商业化痛点

#### 🔐 安全 & 权限类（商业项目重中之重）

6. **无用户体系与细粒度权限控制**：没有账号登录、RBAC 权限、角色管理；没有区分管理员 / 普通用户，任何人访问地址都可以直接使用大模型，无法做用户隔离、资源配额管控。
7. **缺少内容安全审核**：没有输入 / 输出内容风控、敏感词过滤、违规内容拦截，商业化上线存在合规风险（生成违规内容、泄露信息等）。
8. **通信无加密**：默认 HTTP 传输，没有 HTTPS；对话明文传输在局域网 / 公网内，存在聊天记录被抓包窃取的风险。
9. **缺少访问鉴权与防滥用机制**：没有 Token 密钥、验证码、访问频率限流、请求配额，容易被刷请求，耗尽 GPU 算力资源。

#### 📦 数据持久化 & 数据资产类

10. **会话存储在内存中，数据极易丢失**：`session_store` 是内存字典，服务重启、进程崩溃、服务器断电后，所有用户对话记录全部丢失；没有持久化存储。
11. **没有对话管理后台**：无法查看、检索、导出、归档用户对话记录；不支持管理员追溯历史对话，不满足企业审计、留痕合规要求。
12. **没有数据隔离与数据脱敏**：无法自动识别对话里手机号、身份证、企业机密等敏感信息，没有脱敏、屏蔽能力，存在数据泄露风险。

#### 🧠 LLM 能力 & 业务能力短板

13. **没有 RAG 知识库能力**：无法上传 PDF、Word、文档作为私有知识库，模型只能依靠基座本身知识，不能对接企业私有资料。
14. **缺少工具调用（Function Calling）**：不能调用外部工具，无法联网搜索、查询数据库、调用业务接口，只能纯文本对话，很难对接真实业务流程。
15. **模型参数全局固定**：温度、top_p、最大生成长度等参数全局写死，不能给不同会话、不同用户单独配置模型参数。
16. **没有多模型切换管理**：不支持页面一键切换不同 Ollama 模型（Qwen / Llama / Gemma 等），无法根据业务场景选择不同能力模型。

#### 🚀 架构、运维、可观测性

17. **无日志、监控、告警体系**：没有结构化日志，无法统计调用量、Token 消耗、成功率、报错率；没有 GPU 显存利用率、推理耗时监控，出问题很难排查。
18. **无熔断、降级机制**：GPU 显存打满、Ollama 服务挂掉的时候，没有优雅降级、友好报错提示，直接抛出异常给前端，稳定性差。
19. **无容器化部署方案**：没有 Dockerfile、Docker Compose，部署依赖本地 Python 环境，环境迁移、批量部署非常麻烦，不利于交付给客户。
20. **缺少健康检查**：无法自动检测 Ollama 后端服务是否存活；Ollama 崩溃之后，前端只会卡死，不会自动重试、提示后端离线。
21. **没有分布式调度**：只能对接单机 Ollama，不支持多 GPU 节点集群，算力无法横向扩容。

#### 🎨 用户体验 & 产品化

22. **没有对话标签、分类、收藏功能**：用户无法给会话打标签、收藏重要对话，对话多了之后很难检索找到历史会话。
23. **不支持对话导出**：不能把对话导出 Markdown / PDF / Word，不满足用户保存、汇报场景需求。
24. **没有断点续流式输出**：网络抖动、浏览器刷新后，正在生成的回答直接中断，不能恢复继续生成。
25. **缺少响应式适配**：Gradio 原生组件对手机端适配差，移动端布局错乱，只适合电脑端使用。

#### 💰 商业化计费 & 运营

26. **没有计费、用量统计**：没有 Token 统计、算力计费、套餐额度管理，无法实现按调用量收费，不满足 SaaS 商业化模式。
27. **没有工单、客服对接入口**：用户使用问题无法在系统内反馈，缺少运营配套能力。

#### 🧩 兼容性 & 可靠性

28. **强绑定 Ollama**：耦合 Ollama 接口，没有抽象 LLM 后端层，不能一键切换 OpenAI、DeepSeek 等其他大模型服务商。
29. **异常处理简陋**：Ollama 超时、断连、显存溢出时，异常捕获不完善，直接抛出原始 Python 堆栈报错给前端，对用户不友好。
30. **缺少会话过期策略**：长期闲置的会话持续占用内存和上下文，内存会随着使用不断上涨，存在内存泄漏风险。
